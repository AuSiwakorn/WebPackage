# หน้าปิดร้าน 3 คอลัมน์ · หน้าเติม / หยิบเงินแยก · เลิกบัญชีโอน — ออกแบบสั้น

ผู้ใช้ขอ 23 พ.ย. 2569 · อนุมัติในแชต (ทาง ข.) · backup ก่อนแก้: `docs/superpowers/backup/2026-11-23-store/`

## ทำไม
หน้าปิดร้านเดิม (การ์ดบัญชีโอน + การ์ดเงินสด + ฟอร์มเติม / หยิบเงินในหน้าเดียว) ซับซ้อนเกินไปสำหรับพนักงานหน้าร้าน
ผู้ใช้ต้องการหน้าปิดร้านที่อ่านง่าย และเงินในลิ้นชักต้องตรงทุกวัน

## สิ่งที่ผู้ใช้ตัดสินแล้ว
1. ฟอร์มเติมเงินทอน / หยิบเงินออก → หน้าใหม่ในเมนู · เงินสดอย่างเดียว (ไม่มีช่องทางโอน) · สิทธิ์ “เงินเข้า / ออกลิ้นชัก” (`cash`) เป็นสิทธิ์เข้าเมนู · เอาออกจากหน้าเปิด / ปิดร้าน
2. เลิกกรอกยอดในแอปธนาคาร — **ทาง ข. ลบโค้ดส่วนบัญชีโอนออก** (ไม่ใช่สวิตช์) · “ถ้าจะเอาก็ค่อยเขียนใหม่” · คอลัมน์ในฐานข้อมูลไม่ลบ
3. หน้าปิดร้าน 3 คอลัมน์: เงินทอน (เริ่มวัน · เติม · ทอนเงินสด · หยิบออก) | ขายเป็นเงินสด (จำนวนบิล · รับเงินสด · เงินสดรวม) | ขายเป็นเงินโอน (จำนวนบิล · ยอดโอน)
4. ช่องนับเงินได้จริงอยู่กลางใต้ 3 คอลัมน์ · ต้องตรงกับยอดควรมีในลิ้นชักถึงกดปิดได้
5. เงินขาด / เกินจริง → บันทึกส่วนต่างที่หน้าเติม / หยิบเงิน (ขาด = หยิบออก · เกิน = เติม พร้อมเหตุผล) แล้วยอดจะตรง
6. ปิดร้านของวันก่อนที่ลืมปิด → เหมือนเดิม (ไม่ตรงได้ ต้องมีหมายเหตุ) · ปิดย้อนหลังของผู้ดูแลไม่เปลี่ยน

## ทางที่พิจารณา (บัญชีโอน)
- ก. สวิตช์ `bank_track` ใน `active_features()` — แก้น้อย เปิดกลับได้ · ผู้ใช้ไม่เลือก
- ข. ลบโค้ด — **ผู้ใช้เลือก** เพราะถ้าจะกลับมาใช้จะออกแบบใหม่ ไม่เหมือนเดิม

## การตัดสินของผู้สร้าง (แก้ได้)
- ช่องนับเงินเริ่มว่าง (เดิมเติมยอดควรมีไว้ — บังคับตรงแล้วจะกดผ่านได้โดยไม่นับ)
- บิลสด + โอนนับทั้งสองฝั่ง · บิลยกเลิกไม่นับ · ตารางรายการโอนรายบิลตัดออก
- คืนเงินสดอยู่คอลัมน์ 2 · ทอนเป็นโอน / โอนคืนอยู่คอลัมน์ 3 (ขึ้นเฉพาะวันที่มี)
- การ์ดสินค้าที่ขายวันนี้อยู่ล่างสุดเต็มแถวทุกวัน
- เซิร์ฟเวอร์ตรวจซ้ำก่อนปิด (กันเครื่องอื่นขายเพิ่มระหว่างนับ)

## ช่วงงาน
1. หน้าใหม่ `cash.php` + เมนู + สิทธิ์ · เอาการ์ดออกจาก store.php
2. ลบโค้ดบัญชีโอน (ขอบเขตแจ้งก่อนเริ่มช่วง)
3. หน้าปิดร้าน 3 คอลัมน์
4. นับตรงถึงปิดได้ + ลิงก์บันทึกส่วนต่าง
5. เอกสาร + ทดสอบ
